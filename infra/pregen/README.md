# 개선 1: 경계 타일 미리 생성 (terre-lab 전용)

11/6 구성(compose.lab.yml)은 그대로 두고, 이 폴더의 파일을 **덧붙여서** 개선 1을 적용한다. 빼면 바로 11/6 구성으로 돌아간다.

## 무엇을 바꾸나

| 데이터 | 지금(11/6) | 개선 1 |
|---|---|---|
| 행정구역 타일(시군구·읍면동) | 요청마다 DB(PostGIS)가 만듦 | 한 번 만들어 둔 파일을 nginx 가 바로 줌 |
| 보호지역 타일 | 요청마다 DB가 만듦 (즉시 숨김 요구 때문) | 파일로 주되, 공개 상태가 바뀌면 5초 안에 감지해 파일을 내리고 다시 만듦. 다시 만드는 동안은 DB가 지금처럼 그림 |
| 그 밖(줌 13~14, 한국 밖, 다른 API) | backend | 그대로 backend |

- 타일 내용은 backend 응답을 그대로 저장한 것이라 화면 결과가 같다. 응답 헤더(Content-Type, Cache-Control)도 backend 와 같게 맞췄다.
- 앱 코드와 타일 주소는 바꾸지 않는다. 바뀌는 것은 nginx 설정과 작은 생성 서비스(tilegen)뿐이다.
- 확인용 응답 헤더 `X-Tile-Source: pregen | backend` 로 파일에서 나갔는지, backend 가 만들었는지 볼 수 있다.

## 파일

| 파일 | 하는 일 |
|---|---|
| compose.pregen.yml | compose.lab.yml 위에 덧붙이는 설정. web 의 nginx 설정을 바꾸고 tilegen 서비스를 더한다 |
| nginx-pregen.conf | nginx-1106.conf 에 미리 만든 타일 경로만 더한 설정(파일이 있으면 파일, 없으면 backend) |
| tilegen.py | 타일을 backend 에서 한 번씩 받아 파일로 저장하고, 보호지역 변경(레이어 목록 지문)을 5초마다 확인 |
| variant.sh | 구성 바꾸기(base ↔ pregen)와 상태 보기. 첫 생성이 끝날 때까지 진행 상황을 보여 준다 |
| summary.py | 생성 상태 요약 |
| hide_test.py | T6 보호지역 즉시 숨김 시험(실험실 DB 에서 종류 하나를 잠깐 비공개로 바꿨다가 되돌림) |

## 순서 (로컬 PC에서 더블클릭)

1. **4-lab-apply.cmd → 1**: 개선 1 적용. 첫 생성에 15~40분(예상). 창을 닫아도 서버에서 계속된다. 팀 CI 가 돌면 생성을 잠깐 멈췄다가 이어간다.
2. **2-lab-test.cmd → 1, 2**: T1·T2 다시 측정(개선 1 결과)
3. **2-lab-test.cmd → 7**: T6 보호지역 즉시 숨김 시험(10~60분)
4. 필요하면 **4-lab-apply.cmd → 0**: 11/6 구성으로 되돌리기(기준 T6 를 잴 때 등)

## 안전

- 실험실(terre-lab) 컨테이너·볼륨만 다룬다. tilegen 도 실험실 자원 상한(terrelab.slice) 안에서 돈다.
- tilegen 은 실험실 backend 에만 요청한다. 운영 서비스와 운영 DB 는 건드리지 않는다.
- T6 은 실험실 DB 의 보호지역 종류 공개 여부만 잠깐 바꾸고, 끝나면(오류가 나도) 되돌린다.
- 9-lab-down 하면 tilegen 과 미리 만든 타일 볼륨도 함께 지워진다.
